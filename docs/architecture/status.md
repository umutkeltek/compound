Panel blocked-run guidance note: panel runs that stop at no-lane, metered-budget, budget-limit, or target-failure boundaries persist `next_action` alongside `stopped_reason`, so `panel show` / `--json` consumers know whether to refresh route evidence, create a bounded new plan, or inspect route evidence before retrying.

Panel target-provenance note: memory-candidate panel targets produced by `knowledge_extraction` include read-only `source_provenance` joined from `inbox/knowledge-extractions/kx_*.json` (evidence ref, source kind, request state, candidate count, and extraction route model/usage), so lenses judge evidence strength from the extraction request without mutating candidate files or memory truth.

Panel memory-review note: `compound panel plan --target-kind memory_candidate` defaults to current `proposed` memory candidates, matching `orient --operator` actionable memory debt. Explicit `--state parked` remains available for parked backlog review, but parked memory candidates are not the default review queue.

Panel public-knowledge privacy note: proposed arXiv `knowledge_extraction` memory candidates default to not privacy-sensitive, carrying `privacy_default:not_sensitive:public_arxiv_memory_candidate`, so public paper-review panels use ordinary non-sensitive route lanes without requiring operator override. Other memory candidates remain privacy-sensitive by default.

Panel spend-gate note: `GatewayCaller` panel runs refuse metered route lanes (`cheap`, `premium`, etc.) unless the plan carries an explicit `--max-usd-micros` cap; budget-only caps still require `--max-items` or `--max-tokens` because lane cost metadata is not yet enforceable. Fixture/local non-spending callers are unaffected.

Panel local-context preflight note: `GatewayCaller` can preflight LM Studio `/api/v0/models` metadata and block before any model call when a served local model is loaded below required context. By default the required context is the model `max_context_length`; `compound panel run --host-context-limit N` or `COMPOUND_PANEL_HOST_CONTEXT_LIMIT=N` caps the requirement for task/host-adaptive runs while preserving the local-routing owner for actual reload/unload. Local LM Studio default URLs (`127.0.0.1:1234`, `localhost:1234`, `[::1]:1234`) enable the preflight automatically and persist `next_action` for reload/verify retry.

Local-model lifecycle note: `compound local-models advise` is Compound's non-mutating policy/advice surface for required local model context and idle unload candidates. Actionable findings carry structured `lifecycle_intent` records (`owner=local-routing`, local reversible mutation, adapter delegation) so callers can hand off load/reload/unload requests without scraping human steps. For constrained/shared hosts, `--conserve-memory` plus `--max-loaded-models N` emits `pipeline_advice` with sequential/batched lease steps and release intents, so a runner can do one model first, then the next, instead of keeping every required model resident. It reads the local provider base URL through the configured local routing CLI by default, then uses runtime metadata as evidence; the routing layer remains owner for provider routing and any actual load/reload/unload command path.

Panel route-proof note: panel apply receipts include route evidence refs from lens and judge calls as proof refs, so route outcome review can resolve receipt-linked route evidence or report explicit ambiguity for multi-call panel runs instead of losing the execution trail.

Panel execution-failure note: `compound panel run` persists target execution failures as `status=failed` with `stopped_reason`, instead of leaving no-verdict runs in `running`; route evidence already recorded before the failure remains available for diagnosis.

Panel run-apply note: `compound panel run --plan ... --fixtures DIR --apply` or gateway flags with `--apply` executes the dry run first and calls `panel.Apply` only after `verdicts_recorded`; standalone `--apply` keeps the existing apply-only path.

Panel domain-lens note: `panel lenses` and `panel plan` accept `--domain` / `--task` context. Known domains such as `paid-app` and `social-distribution` select reviewed domain lenses; unknown domains keep generic lenses but write a deterministic `capability_observation` gap candidate instead of silently treating generic coverage as complete.

Skill-surfacing feedback readiness note: consumed skill-surfacing feedback reports with no remaining/proposed/all-miss items are terminal in `orient --operator` only when matching source/no-promote evidence exists for their content hash; unconsumed feedback still surfaces actionable.

Proof-check status note: `compound proof-check [--json] [--dry-run] [--repo P]` runs the deterministic local verification bundle: `go test -count=1 ./...`, `go vet ./...`, `go build ./...`, `git diff --check`, strict architecture doctor, memory doctor, and public redact scanning of changed files. ## Commands

External repo intake surface note: `capability external-intake --source-list <file>` keeps aggregate/source-list counts plus bounded next-action queues in human output and omits known row details behind `--json`, so large repo lists stay operator-readable without losing evidence. `external-intake-import-reviewed --source-list <file>` explicitly imports reviewed manifests into CapabilityGraph authority; `needs_review` nodes remain non-surfacing, so imported does not mean served/adopted.

Dispatch read-model status note: Workbench resolves recorded dispatch-step waits to `status=resolved` / `wait_reason=terminal_work` when every blocked work ref is already terminal, and resolves historical `no_open_work` waits as no-op summaries, without rewriting old run files; operator orient hides resolved/no-op dispatch history from the RUNNING triptych.

Distiller request record note: `distiller request --record` artifacts under `reviews/distiller-requests` annotate the review queue as recorded replay packets with source refs, not human review debt; invalid request JSON remains blocked.

Hook input hash note: context-producing hooks hash normalized hook, harness, cwd, task, repo-kind, mode, and prompt digest, so same prompt/task in different scope does not collide and raw prompt text stays out of artifacts.

Hook context side-effect note: context-producing hooks list the full persisted artifact chain in `HookEvent.side_effects`: redacted request, dated EffectiveContract, ContextPack, and harness-facing injection markdown; `output_ref` points directly at injection markdown, whose `Capability Offers` section renders surfaced offer refs/names/constraints before budgeted provenance/decision lists while full refs remain in ContextPack JSON.

Distiller runtime-source note: `distiller.LoadRuntimeSources` follows safe relative JSON `HookEvent.side_effects`, validates typed envelopes, dedupes already-loaded work/context artifacts, includes ContextRequest/EffectiveContract envelopes as grounded extraction sources, preserves HookEvent `output_ref` in structured LLM envelopes, and includes output refs in request `source_refs` so grounded extraction can cite them.

Active packet proof note: `work active-packet-proof --source-packet <packet.md>` and `workbench --source-packet <packet.md>` compare the current packet evidence ref against the proof chain, so stale terminal packet proof reports risk instead of `source_packet_terminal`.

CLI safety note: `compound capability ... --help`, plus guarded `work`, `memory`, and `route cost-doctor` subcommand help paths, return usage before opening runtime state, so help requests cannot consume receipts, import graph data, validate work/memory fields, or open provider ledgers.

Contract command status note: `compound contract compile` records durable EffectiveContract artifacts under `COMPOUND_HOME/contracts/effective/<date>/<id>.json` and `latest.json` while preserving stdout JSON; `compound orient` records the matching EffectiveContract artifact before recording ContextPack artifacts under `COMPOUND_HOME/context/packs/<id>.json` with matching `ids.contract_id`; hook context-injection paths persist the same contract->pack artifact chain.

ContextPack hook status note: active hook refs appear in both `active_hooks`/`hook_roster` and `included[]` with runtime/current reasons, while task-excluded hooks remain in `excluded[]`; mutation contexts with adapter-required write-gate readiness add `required_checks[]`, so consumers see the enforce command before writes.

Hook context mode status note: hook context artifacts use one requested-mode decision for both `ContextRequest.requested_mode` and `EffectiveContract.task_mode`: `session-start` orients in `observe`, while `user-prompt-submit` creates execute-mode proposed work context.

Hook event identity note: `HookEvent` IDs include the normalized input hash, so same-second hook runs with different task/prompt/action inputs do not overwrite persisted hook events or context injection artifacts.

Receipt consumer status note: `Receipt.EffectiveChanged` is the read/consume rule for Workbench, operator orient, and CapabilityGraph receipt mining; completed proof-bearing non-`audit_only` receipts count changed even if an older receipt stored `state_delta.changed=false`; Workbench recent items surface `Receipt.proof_refs[]` as `evidence_refs[]`, and operator orient changed/recent rows carry those Workbench evidence refs so receipt-only proof chains remain operator-visible.

Capability evaluation surfacing note: evidence-only evaluation nodes never surface as offers, but matched evaluation evidence can lift the already-known owner attached by `evaluated_by` / `validated_by`.

Product authority status note: `compound product authority [--json]` is the read-only product feedback authority report over existing ledgers and candidate stores.

Synthesis status note: `compound synthesis sweep [--stage cluster,contradict]` keeps cluster proposals report-only, while contradiction sweeps may append `needs_review` claim markers when proposed evidence contradicts a promoted current claim. It still does not adjudicate candidates, promote, reject, or supersede claims; reopened claims leave ambient recall until explicitly resolved and surface review debt through sweep/review artifacts.
