# Kernel Contracts (the lego seams)

Fragmentation happens when seams between pieces are fuzzy: change one and others break. The cure is
a small explicit contract — port + lifecycle + receipt — with implementations swapped behind it.
Defined before implementation so agents stop re-deriving them. Implement a contract only when a
vertical slice needs it (`../../roadmap/phases.md`).

> Public/private rule (`../../BOUNDARIES.md`): the *contract* and generic lifecycle are public. Instances
> carrying personal paths, credentials, accounts, or private bodies live in the private overlay
> (`docs_private/`, gitignored) or an out-of-repo adapter — never a tracked file.

## Envelope-spine contracts (first-order — the runtime grammar)

Context orientation resolves repo kind by explicit flag, committed `.compound/repo.yaml`, private `COMPOUND_HOME/config/repo-kinds.yaml`, then product default. Product repos exclude control-plane governance refs with recorded reasons; control-plane repos include them.

These are the typed objects every harness/hook/run flows through, hung off one root **`work_id`**. Export machine-readable JSON Schemas with `compound schema export <name>` or `compound schema export --all --dir <dir>`; validate concrete files with `compound schema validate <name> <file>`. Runtime semantics still live in the owning package validators.

Hook adapters normalize relative `ActionIntent.target.path` values against hook `cwd` before policy evaluation,
artifact persistence, and source-control inspection. Policy reasons, stored ActionIntent artifacts, and git evidence
therefore refer to the same governed target.
Placement guard evidence is also runtime policy context, not a second guard path: PreToolUse can pass
`PlacementGuard` context into `PolicyDecision`, staged `observe -> warn -> block`; only `confidence:block`
can hard-hold, `OPEN_WRITE` / `PLACEMENT_OVERRIDE=1` fail open, unknown modes fail open as observe, and
`hook pre-tool-use --enforce` carries the resulting Gate exit code for wrappers.
`compound policy import-placement-rules <placement-rules.json>` imports generated owner placement rules
into `COMPOUND_HOME/registries/placement-rules.json` as `compound://registries/placement-rules`; after
that handoff the generated source view is evidence/rollback input, and PreToolUse reads the Compound copy.

| Contract | Purpose | Lifecycle |
|---|---|---|
| **EffectiveContract** | the compiled "what applies right now" artifact every run references by `contract_version = sha256(...)`; kills global instruction bloat | compiled-per (harness, cwd, task) |
| **ContextRequest** | what a hook asks compound for | per hook event; `hook session-start` persists a redacted request under `COMPOUND_HOME/context/requests` with `intent_text_ref` as hash-only, never raw prompt |
| **ContextPack** | frozen context an agent consumes; records included AND **excluded** refs + reasons → enables replacement | immutable per work/session. `compound orient` appends surfaced `CapabilityGraph` offers as generated included refs when graph state exists, filtered by `surfaces_with -> harness:*` compatibility when present; structured `capability_offers[]` carries score, why, required refs, harness compatibility, conflicts, missed/false-trigger risks, evidence, and the offer-only execution boundary. Offers are not execution. | **WorkEnvelope** | the one root identity for a unit of work (carries the JobUnit fields: desired_outcome, success_predicate, non_goals, risk + the id chain) | proposed → admitted → ready → claimed → running → verifying → completed \| held \| blocked \| failed \| cancelled. `work import-packet <packet.md>` turns markdown execution/goal packets into deterministic WorkEnvelopes keyed by packet hash, carrying packet evidence refs/source revision while not mutating the packet, closing work, promoting memory, or claiming success. | **ActionIntent** | a proposed mutation, pre-policy (capability, target, mutation_class, reversibility, blast_radius, rollback_plan) | per proposed action |
| **PolicyDecision** | the governance verdict an adapter **enforces** (allow \| allow_with_obligations \| hold \| deny + obligations) | per ActionIntent |
| **StandingGrant** | a pre-authorized envelope (capability/mutation class plus scope/budget/blast-radius/reversibility constraints such as `target_path`, `max_usd`, `max_tokens`, `blast_radius`, `reversibility`) so agents act inside it without paging; leaving the envelope falls back to `PolicyDecision` hold/deny through the same gate | granted → expires/revoked |
| **HookEvent** | one normalized harness lifecycle event (capability, input_hash, side_effects, status, ids{work_id,context_pack_id}) | append-only; persisted as `events/<hook_event_id>.json` plus `events/hook-events.ndjson` when `COMPOUND_HOME` is available |
| **Receipt** | how a run is learned from — proportional to risk/blast-radius (state_delta, `delta_cause`, cost, skills, memory, `next_consumer`, `opens_branches[]`, `move_type`) | append-only; mined. `skills.used` is derived from allowed recorded ActionIntents; `skills.candidate` is derived from ContextPack capability offers; close/session-end auto-consume receipts into CapabilityGraph feedback when graph state already exists. Explicit feedback can be emitted by `work close --missed ... --false-triggered ...` or `hook session-end` fixture fields; unused candidates are never inferred as feedback. |
| **Transition** | the apex object joining projections (`../transition.md`) | append-only; emits second-order signals |

`work_id` is **the** anti-fragmentation object — one root id linking
intent→context→action→policy→run→receipt→transition replaces scattered packet/run/provider/receipt/slug ids.
Governance is enforced at adapters: **a mutating adapter rejects a mutation lacking a valid `PolicyDecision`**.

| **MemoryEngine** | rented breadth index — **bridge/index, never authority** | protocol lives with spine memory (`internal/mem/protocol.go`); target port: `Query/Recall/PutProjection/Build/Health/ExplainResult`. Swap proof: `memory engine-compare` compares a configured sidecar against the owned lexical reference on hydrated claim ids while keeping ledger bytes unchanged. `compound-memory-cli-engine` is the first read-only existing-store sidecar on this port. It calls a configured external memory CLI only as rented expansion context, returns only claim ids from the current Compound index allowlist, maps broken backend calls to `ErrEngineUnavailable`, and rejects mutating command templates before the external CLI is invoked. `COMPOUND_MEMORY_CLI_PROFILE` selects built-in read-only presets for known local memory CLIs; `COMPOUND_MEMORY_CLI_BIN`, `COMPOUND_MEMORY_CLI_QUERY_ARGS`, and `COMPOUND_MEMORY_CLI_ENGINE_EMBEDDER` remain explicit overrides so presets do not become spine dependencies.

`memory engine-compare` is exact by default. Use `--allow-expansion` for semantic or legacy-memory sidecars: reference hits must remain covered, degraded sidecars still fail, ledger bytes must stay unchanged, and extra allowlisted current claims are reported as `expansion`, not authority.

It does not mutate gateway/provider/model-router config, does not claim task success, and does not promote claims.

Product source issue note: `product change-stream <candidates.md>` imports mined change-stream promotion candidate pages as product-scoped source issues through idempotent `NoPromoteDecision` rows. These records preserve source hash/capture, product, surface, repo, score, and dirty-preview evidence, and they are visible through `product timeline` / `product doctor`; they are not durable product changes, product signals, hypotheses, metric claims, or source mutations. `product source-issue-plan --product <id> --issue <id> [--target <file>]` writes JSON/Markdown closure-planning artifacts plus a gated `.review.yaml` draft under `COMPOUND_HOME/reviews/product-source-issues/` without closing the issue. The YAML draft carries original evidence and an invalid placeholder result so it cannot pass `product source-issue-review <review.yaml>` until a reviewer explicitly selects `resolved|waived|false_positive`; optional reviewed `follow_up` is candidate-only and enters the existing ProductHypothesis review path.

## Distillation & capability-growth contracts (the compounding layer — P6 continuation + P8)

These turn traces into *adjudicated, versioned* knowledge and grow capability from evidence. They **extend**
the candidate loop and the `Claim` / `Capability` / `RegistryEntry` rows above — they do not replace them.
Defined here; implemented when a slice needs them (the candidate fan-out + as-of recall already exist in
`internal/mem`). Invariant throughout: **model extracts, code decides; no candidate reaches ambient recall
unadjudicated; distillation proposes candidates only.**

`LLMExtractionRequest` is the provider-neutral request packet. It carries bounded raw trace text,
prior-state coverage, bounded `prior_signals[]` critique history, source refs, typed summaries of ContextPack, WorkEnvelope, Receipt, explicit
`capability_feedback[]` derived from `Receipt.skills.missed` / `Receipt.skills.false_triggered`
(never `skills.candidate` offers), and extra spine envelopes including `TraceEnvelope` event evidence.
`prior_signals[]` includes distiller self-improvement history (`method_upgrade`, `policy_patch`, `eval_case`)
and active no-promote rows, so rented extractors can avoid repeating known rejected/duplicate ideas without seeing all memory.
TraceEnvelope summaries preserve structured source/scope/mutation/files/tools/output metadata so a rented extractor can use event evidence without raw event-body access or promotion authority.
It can be assembled from explicit typed files, from a closed `COMPOUND_HOME` work chain via
`distiller request --work-id <work_id>` including matching HookEvents from
`events/hook-events.ndjson`, or from imported event traces via `distiller request --event-trace <trace_id>`.
It is prompt material only, not a model call and not authority.

`ConversationMiningImport` adapts generated conversation-mining reports and mined tag rows through `compound distiller import-conversation-mining <report.json> [--mined-tags rows.jsonl] [--lossiness lossiness.json]`. It records lossiness/known lossy corpus rules, accepted/rejected/source-quality counts, provider mix, and accepted-for-review rows as `SourceObservation -> method_upgrade candidate -> NoPromoteDecision`, then prints the exact reviewed next step `compound distiller improvement-plan --candidate <id>`. It has no Dream execution, no memory promotion, no source-owner mutation, and facts still require distiller extraction plus adjudication or reviewed write-plan.

`ConversationCoverageImport` adapts generated conversation corpus coverage summaries through `compound distiller import-conversation-coverage <summary.json>`. It is summary-only: source counts, mapped/unmapped clean coverage, retained-ratio signal, Dream-candidate counts, missing embeddings, and top-tag count become `SourceObservation -> method_upgrade candidate -> NoPromoteDecision`, then the CLI prints exact reviewed next step `compound distiller improvement-plan --candidate <id>`. It has no row import, no Dream execution, no memory promotion, no source-owner mutation, and no raw conversation/body ingestion.

`LLMExtractionResponse` is the provider-neutral model-output adapter for TraceDistiller. It carries
`schema_version`, `trace_ref`, `source_refs[]`, and `candidates[]`; code normalizes it into `Trace`.
Unknown kind, missing confidence, malformed JSON, or model-supplied `promotion_basis` is invalid.
Eval/live extraction is request-grounded: every candidate must include `evidence_refs[]`,
and each candidate evidence ref must exist in the originating `LLMExtractionRequest.source_refs[]`.
Candidate shape is also guarded before inbox write: memory candidates require `entity`,
`predicate`, and `object`; non-memory candidates require `subject` and `statement`.
Ungrounded model citations fail before candidate inbox write; model output still cannot promote memory directly.

Unknown evaluated capabilities are reported as `status: review` with `skipped_unknown_count`; `capability evaluation-plan <eval.json|dir> --capability <id-or-name>` turns one unknown evaluation into `COMPOUND_HOME` owner-review artifacts plus a normalized `compound.skill_manifest.v0.1` draft marked `needs_review`; `capability evaluation-review <review.yaml>` validates an edited review decision and writes a reviewed manifest, while only `import-skills` mutates the graph and active reviewed manifests surface. `capability surface [--harness <harness>] --json "<task>"` is the read-only machine surface for compatibility callers and returns `authority_ref: compound://registries/capability-graph`; callers may consume offers but still cannot execute without WorkEnvelope/ActionIntent/PolicyDecision. receipt consumption mines completed, changed `Receipt.skills.used` into `validated_by` edges, explicit `Receipt.skills.missed` into `missed_when` context edges, and explicit `Receipt.skills.false_triggered` into `false_triggered_by` context edges while ignoring `skills.candidate` offers; `work close` / `hook session-end` trigger this automatically when graph state exists, and `capability consume-receipts` replays it manually; **auto-surface, never auto-execute** |

`SkillManifestAdapter` is the skill-import seam for this graph: it imports strict versioned skill/lens/procedure manifests and read-only generated skill-manifest JSON into `CapabilityGraph`, records compatible harnesses as graph edges, treats needs_review/deprecated/retired as non-surfacing, and never runs imported procedures. Generated skill views are normalized into the same manifest contract as evidence-backed offers; they do not become a second skill registry.

The self-improving loop is what makes this *compound*: the distiller's own misses/false-triggers and a
capability's `missed_when` / `false_triggered_by` edges become evidence that patches the next
DistillationPolicy and re-weights surfacing — repeated success becomes infrastructure, repeated failure
becomes a rule, **only after evidence** (Laws 7/8).

Operationalized `capability_observation` candidates are the distiller/critic feedback seam into CapabilityGraph. `distiller run` consumes them automatically only when graph state already exists; `capability consume` remains the manual replay/repair command. A distiller run never creates graph state by itself and never executes capabilities.

`compound harness observe [registry.yaml|--os-entrypoints file]` records built-in,
normalized external, or OS-style harness entrypoint support/limitations as
`SourceObservation -> capability_observation candidate -> NoPromoteDecision`. OS-style
entrypoint imports infer only `session_start_context`; hook blocking, post-tool events,
receipts, skills, and MCP support require an explicit normalized capability registry.
The adapter does not install hooks, mutate CapabilityGraph nodes, or treat registry
defaults as authority.

## Authority & governance contracts (the under-modeled organs — Axis B)

These are the **inside-world registry and governance** seams that plain `Claim`s under-model
once agents *act* on infra, decisions, and writeback. Generic and public — no private owner
names (the named OS→contract mapping lives in `docs_private/plan/os-coverage-matrix.md`).

Runtime live proof is opt-in: a bundle may declare `runtime_probes[]` with `http`,
`tcp`, `file`, or `env` probes. `compound runtime doctor <bundle> --live` appends
`live:<probe_id>` checks to the same report; without `--live`, runtime doctor
remains structural. `runtime repair-plan ... --live` routes live failures through
the same gated owner-review path.

First slice: `compound runtime doctor <bundle>`; infra-os adapter: `compound runtime doctor --project-contract <project.yaml>`; failing reports can use `compound runtime repair-plan ...` to record gated owner-review artifacts under `COMPOUND_HOME` without mutating owner files |

### Generated views

`GeneratedViewObservation` is the contract for generated instruction/dashboard/registry
views. It records `view_ref`, `source_refs[]`, `output_hash`, `source_hashes[]`,
`generator`, `consumer`, `marker_status`, `freshness`, and the object family it maps
to. It may create `ProjectionFreshness`, evidence, or a parked/no_promote candidate.
It cannot promote truth by itself.

Capability graph imports add a source-authority handoff after successful topology or skill-manifest import: `compound capability import-topology` and `compound capability import-skills` write `registries/capability-source-authority.jsonl`, mark `compound://registries/capability-graph` authoritative, mark the imported source view `evidence_only_input`, and retire `source_view_authority:<source_path>`. The source file remains rollback/evidence input; the graph is the consumer authority.

Build order (most likely to let fragmentation back in first): **OwnerWritebackGate/NoPromoteDecision** first slice landed; `projection doctor --writeback`, `runtime doctor --writeback`, and `decisions doctor --writeback` consume it for stale/drifted generated views, failing runtime reports, and decision lifecycle gaps. `runtime repair-plan` consumes the same runtime writeback gate and emits JSON/Markdown owner-review artifacts for runtime contract repair without editing owner files. `projection doctor --source-observe` and `projection dashboard-read-model --source-observe` convert stale/drifted freshness into the same `SourceObservation -> method_upgrade candidate -> NoPromoteDecision` path used by source adapters, so generated-view drift does not live in a report-only side channel. `projection doctor --record-context` and `projection dashboard-read-model --record-context` persist scoped `ProjectionFreshness` records that `orient` can include as generated context evidence. `projection repair-plan` consumes both paths and emits review artifacts for owner regeneration without running a generator or editing the generated view. `distiller run` now records duplicate memory outputs and duplicate non-memory candidate meanings as idempotent `NoPromoteDecision` rows instead of letting them re-enter as new work. `source observe` maps generated/source observations into candidate inboxes plus explicit no-promote rows; it observes existing owners and cannot promote truth. `capability import-topology` maps observed tool/MCP topology, generated resolver JSON, or `mcporter list --json` catalog output into CapabilityGraph nodes and fallback edges while recording the imported topology source as no-promote capability observation evidence; `capability import-skills` maps normalized manifests or generated skill-manifest JSON into CapabilityGraph offers while recording the manifest source as no-promote capability observation evidence; `capability import-evaluations` maps scored capability-evaluation records into eval graph nodes and evidence edges for already-known capabilities while recording the evaluation source as no-promote capability observation evidence; `capability evaluation-plan` turns one unknown evaluated capability into review artifacts plus a `needs_review` skill-manifest draft, and `capability evaluation-review` turns an edited review decision into a reviewed manifest without graph mutation. work/session closure auto-closes the runtime feedback loop when graph state exists, and `capability consume-receipts` replays the same idempotent path. None of these commands execute tools or skills.
Each is **defined here before implementation** so agents stop re-deriving them; each is built
only when a vertical slice needs it (`../../roadmap/phases.md`).

## Entity resolution — the precedence order (the root of anti-fragmentation)

`NotesApp` / `notes-app` / a bundle id / "that app with the metrics" must collapse to **one** entity:

```text
1. explicit compound entity id
2. registry alias
3. repo / app / product fingerprint (remote, bundle id, package name, deploy target)
4. scope-resolver match ABOVE a confidence threshold
5. otherwise → a NEW candidate entity, PARKED until reviewed
```

An **uncertain** match creates **parked evidence only — never a promoted claim.**

## Shared fields that bend behavior

- **`source_class`** (on the universal header) — `source | generated | evidence | review | runtime |
  private_overlay`. Prevents *retrieved ≠ relevant ≠ authoritative ≠ current*. Only some classes are ambient.
- **`second_order_risks[]`** — every affordance is an attractor; declare what it makes more likely and can
  fossilize/flatten (`../transition.md`). Selection is ensemble-aware, not lookup.
- **`temperature` (memory) / `move_type` (receipts)** — make Law 5 and Law 15 measurable. Canonical
  `move_type` enum: `outward_delta | memory_delta | rule_delta | control_plane_repair | audit_only`. A
  `control_plane_repair` only counts when it removes a duplicate owner, fixes a recurring failure, or creates
  runtime proof — otherwise `audit_only`, which does not count.

## Distiller Improvement Review Gate

`compound distiller eval <case.json|cases-dir> --record` stores passing eval proof under `COMPOUND_HOME/reviews/distiller-eval/proofs/` and prints a `distiller_eval:*` or `distiller_eval_corpus:*` proof ref. `compound distiller improvement-plan --candidate <id>` writes JSON/Markdown review artifacts plus gated `.review.yaml` under `COMPOUND_HOME/reviews/distiller-improvements/`. `compound distiller improvement-review <review.yaml>` validates edited decision/rationale/confidence, requires `eval_proof_refs` for accept, and resolves each accepted proof ref to a recorded passing eval proof before emitting a reviewed improvement artifact. It does not mutate distiller policy, edit prompts/code, update eval corpus, call a model, mutate source owners, or promote memory truth.
