# Kernel Contracts (the lego seams)

Fragmentation happens when seams between pieces are fuzzy: change one and others break. The cure is
a small explicit contract — port + lifecycle + receipt — with implementations swapped behind it.
Defined before implementation so agents stop re-deriving them. Implement a contract only when a
vertical slice needs it (`../../roadmap/phases.md`).

> Public/private rule (`../../BOUNDARIES.md`): the *contract* and generic lifecycle are public. Instances
> carrying personal paths, credentials, accounts, or private bodies live in the private overlay
> (`docs_private/`, gitignored) or an out-of-repo adapter — never a tracked file.

## ProductObservationVerdict Contract
ProductObservationVerdict contract note: `compound product observation-verdict-plan --verdict <panel-verdict.json>` consumes product-subject `capability_observation` panel verdict evidence into `reviews/product-observation-verdicts` / `product-observation-verdicts`; `compound product observation-verdict-review <review.yaml>` records a product-owned decision and may create a parked `product_hypothesis` candidate. It does not apply panel verdicts, mutate ProductSignal, call external accounts, post/reply/spend, promote memory, or create observation truth authority.

## SourceObservationVerdict Contract
SourceObservationVerdict contract note: `compound source observation-verdict-plan --verdict <panel-verdict.json>` consumes non-product/source `capability_observation` panel verdict evidence into `reviews/source-observation-verdicts` / `source-observation-verdicts`; `compound source observation-verdict-review <review.yaml>` records source-owned `NoPromoteDecision` or unsupported no-owner parked evidence. It does not apply panel verdicts, mutate ProductSignal, call external accounts, post/reply/spend, promote memory, or create observation truth authority.

## Panel Capability Feedback Contract

Panel capability feedback note: `compound panel feedback-plan --verdict <panel-verdict.json>` consumes panel verdict lens findings into `reviews/capability-panel-feedback` / `capability-panel-feedback`; `compound panel feedback-review <review.yaml>` is the explicit review gate that can write reviewed `validated_by`, `missed_when`, or `false_triggered_by` CapabilityGraph feedback edges. `compound orient --operator --json.needs_me.capability_feedback` summarizes pending/applied feedback impact and links `compound capability authority`. It does not auto-mutate CapabilityGraph from unreviewed verdicts, run panel execution, execute tools, promote memory, mutate providers, call external accounts, or create capability truth authority from lens output alone.

## ObservationBatch Contract

`compound.observation_batch.v0.1` is the generic external payload seam. `compound source observe-batch <batch.json> --dry-run --json` validates and route-plans observations into existing owners: product metrics -> `ProductSignal`, content -> `KnowledgeExport`, events -> `TraceEnvelope`, route/cost rows -> `ExecutionRouteEvidence`, generated/system rows -> `SourceObservation`, and social/support feedback -> candidate/review material. `--apply-product-signals` is the bounded product metric apply mode and calls the existing ProductSignal owner. `--apply-source-observations` is the bounded generated/system apply mode and converts `source_observation` route decisions into existing `sourceobs.Apply` candidate plus `NoPromoteDecision` material. `--review-candidates` records candidate-only feedback observations as `capability_observation` candidates and `observation-candidates` review artifacts whose queue card points to `compound panel plan --target-kind capability_observation`; the panel execution path records contextual synthesis as `panel-verdicts` review material through `compound panel run --plan <run_id> --fixtures <dir> --json`. `compound source intake --json` exposes `compound.source_intake_projection.v0.1` from recorded apply/review reports and is also consumed by `compound orient --operator --json.needs_me.source_intake`; it derives action cards for stale, skipped, blocked-private, and unsupported rows with required inputs, expected validation, stop conditions, boundary, proof, and exact command. `compound source intake-work-plan --card <card_id> --json` turns one derived card into a proposal-only Work create-plan with `source_intake_action_card` WorkActionContext, preserving command/gates/proof for Workbench admission previews and later `work admit-plan` -> `advance-plan` -> `claim-plan` -> `action-plan` -> `act` -> `close-plan` lifecycle commands without the work-plan itself executing the card. It is a projection over owner reports, not a second source ledger. Collectors remain rented/private edges and the command makes no external account call, requires no credentials, posts nothing, promotes no truth, does not mutate ProductSignal except the explicit product-signal mode, and does not create provider-specific core authority.
ObservationBatch contract note: every `--apply-*` mode routes one external payload class into its existing meaning owner (ProductSignal / `knowledge.Import` / `routeevidence.RecordJoined` / `eventsource.ImportOSEvents` / `sourceobs.Apply`), producing evidence, candidate, and `NoPromoteDecision` material only — never a new connector-specific meaning/route/event ledger, external account call, or memory promotion.

It is not an external collector, scheduler, provider connector, memory promotion, ProductSignal mutation, public side effect, or a second event truth ledger.

## Event-reference contract

`internal/eventstore` owns the physical layout beneath `COMPOUND_HOME/events`; callers persist and exchange
logical references instead of filesystem paths. The resolver accepts bare IDs, `compound://events/<id>`, and
historical `events/<id>.json` references. It rejects traversal, slash-bearing IDs, absolute paths, and physical
segment/index paths. `events/work.jsonl`, `events/hook-events.ndjson`, and `events/traces.ndjson` remain named
compatibility streams with separate semantics, but their construction and filesystem access stay behind the same
owner seam.

## Work collaboration observation contract

`compound.work_collaboration_event.v0.2` is the multiplayer coordination seam and remains subordinate to the envelope spine; v0.1 records remain readable but are silent on a fresh delivery cursor unless explicitly migrated or reclassified. One `wco_*` event belongs to exactly one nonterminal, leased `work_id`; the recording actor must be the live lease holder. Its payload is bounded metadata only: actor, optional session/target actor, optional same-work `ratt_*`, already-attached same-work causal `wco_*` parents, `visibility=work`, inherited privacy, one compact before/after state delta, relevance refs for actor/work/scope/dependency/policy/base revision/reserved resource, one of `silent_state|next_boundary|interrupt|human_attention`, and a required content-addressed `artifact:sha256:<digest>` body reference that resolves and hash-verifies through the existing artifact-store owner. An idempotency key is scoped to the work and deterministically addresses the complete event semantics; reusing it with different metadata fails closed. Recording requires and attaches an allowing ActionIntent/PolicyDecision, and interrupted attachment retries converge on one governed work-log row.

`compound stream --follow` and finite cursor reads hydrate the governed attachment into typed `collaboration_event` frames while retaining the source lifecycle event and byte cursor. `internal/hookplan` consumes that canonical replay through one persisted recipient cursor, suppresses irrelevant and silent events, queues `next_boundary`, immediately selects exact-run `interrupt`, coalesces compatible deltas into at most one bounded card, and compiles equivalent semantic cards for Codex and Claude-family adapters. Native recipient resolution requires an exact owned session/work/run/harness binding; workspace proximity never adopts an unknown session. A delivered interrupt remains a level-triggered native deny at every PreToolUse until newer relevant governed state supersedes it, without card redelivery. `human_attention` never enters model context: a replay-zero, read-only fold exposes current unresolved reference-only state to the operator projection without consuming a cursor or writing a report or acknowledgement. It hard-caps output at eight items and each item exposes only event/work/class/delta/artifact/semantic-revision refs. Cards likewise contain state deltas and artifact refs only; bodies remain behind explicit artifact retrieval bound to the exact owned native session. An explicitly populated relevance dimension always narrows authorization; a work-level event without a pre-named run may be retrieved only by the current active bound run satisfying the same derived relevance state. Delivery reports persist actual native bytes, deterministic token estimates, and observable action-delta refs. Budget exhaustion holds pending events and fails closed instead of truncating meaning. A later report/state publication fault emits the current native deny without the unpublished card and leaves that card retryable once. Delivery emits no acknowledgement message by default. The stream and delivery state are rebuildable projections: this contract creates no chat/message authority, promotes no memory, and does not let an agent bypass candidate/adjudication or ActionIntent/PolicyDecision paths.

## Envelope-spine contracts (first-order — the runtime grammar)

Evidence-autonomy hardening (binding clarification):

- New terminal lifecycle events seal canonical JSON for both the WorkEnvelope
  (`work_sha256`) and exactly one attached Receipt (`receipt_sha256`).
  Recent autonomy cohorts require one terminal event, one matching
  hot/restored/archived WorkEnvelope, and one Receipt with a matching seal.
  Missing legacy seals remain readable but cannot qualify; post-close edits
  and duplicate identities fail closed.
- Each sample has exactly one well-formed
  `director_trigger:<class>:<identity>`. The eligibility `generated_at`
  must equal the admission instant at UTC RFC3339 precision, so an earlier
  frozen evaluation is not reusable authority.
- Route evidence carries writer-owned `recorded_via`:
  `external_import | generic | trusted_panel_runtime`. Payloads cannot
  assert it. Missing historical values normalize to `generic` for resume,
  but only `trusted_panel_runtime` may decide autonomy.
- No production caller currently mints trusted route provenance. The
  `job_health` implementation is therefore bench-only and fail-closed.
  `operator:*`/`human:*` is also lexical provenance, not authenticated
  OS/user identity; rented executors are not safe grant minters until an
  authenticated authority seam exists.

Context orientation resolves repo kind by explicit flag, committed `.compound/repo.yaml`, private `COMPOUND_HOME/config/repo-kinds.yaml`, then product default. Product repos exclude control-plane governance refs with recorded reasons; control-plane repos include them.

These are the typed objects every harness/hook/run flows through, hung off one root **`work_id`**. Export machine-readable JSON Schemas with `compound schema export <name>` or `compound schema export --all --dir <dir>`; validate concrete files with `compound schema validate <name> <file>`. Runtime semantics still live in the owning package validators.

Git delivery is an additive WorkEnvelope contract, not Git-index authority: `target_worktree_root`, derived `repository_fingerprint`, exact `target_local_ref`, full `expected_base_sha`, and `publication_mode=required` plus a bound remote-tracking ref (or explicit `local_only`) freeze where one final candidate must arrive. Current create/admission rejects partial declarations while legacy envelopes remain readable. An operator-provenance, same-state `work advance` may bind one complete contract to a nonterminal legacy envelope exactly once; a matching legacy base is cleared, while partial binding, rebinding, executor binding, and binding during a state transition fail closed through the normal advance policy/journal path. A pre-fingerprint v0.1 WorkEnvelope with otherwise complete delivery fields preserves its omitted bytes/hash but cannot be claimed, dispatched, prompted, or ordinarily advanced until an exact operator same-state advance derives the fingerprint without changing any other field. `work land-check` verifies the latest attached full commit against that authority and records content-sealed `work/land-checks` reports; only a currently revalidated `landed` v0.4 report attached to the same WorkEnvelope can satisfy completed close. Historical v0.3 reports predate sealed repository identity and require a fresh v0.4 check; they are stale evidence, not tampered current proof. A required publication remains incomplete until the bound `refs/remotes/*` ref contains the candidate. Commit proof arriving through artifacts, close flags, or action-plan drafts cannot bypass a missing contract. On every non-audit move, a typed absolute target surface or persisted mutating ActionIntent resolving inside a Git worktree also requires delivery authority; corrupt or missing ActionIntent evidence cannot erase that signal. ContextPack and canonical-surface orientation alone are not mutation proof. Nonterminal Workbench and close-plan surfaces re-evaluate delivery state, while terminal work remains terminal rather than being offered for close again.
Prediction/Surprise is an additive WorkEnvelope/Receipt contract, the harness-layer prediction-error signal: `WorkEnvelope.prediction` optionally stakes an expected close (`outcome` required, `move_type` optional, both enum-validated) at create time only, and `work close` mechanically diffs it against the actual close into `Receipt.surprise` (`predicted_*`/`actual_*` plus `diverged`) — nil when nothing was staked, always set (diverged true or false) when it was. A staked `prediction.outcome` predicts the CLOSE outcome enum (`completed|failed|cancelled`, i.e. `work close --outcome`), never `Receipt.outcome` (mapped through `cancelled→no_op`) and never the free-text `desired_outcome` staked via `work create --outcome`. A close that diverges from its staked prediction additionally mints exactly one `observed`-derivation memory candidate (`internal/mem.ObserveWorkSurprise`, content-addressed under `COMPOUND_HOME/observed/work-surprise/`, never a ledger byte, never auto-promoting) so prediction error accumulates as adjudicable evidence for the memory inbox, the ACE/injection-observation weekly compile, and the canonized value-function Revisit trigger.
Standing-proof graduation is the sibling additive close-exhaust edge that attacks `landed ≠ working` (close evidence is point-in-time; nothing re-verifies it): when a `work close --outcome completed` seals a WorkEnvelope whose `success_predicate` is command-shaped — classified conservatively by `internal/work.CommandShapedPredicate` (a recognized executable + arg, a real `go` subcommand, or a path-form invocation; plain prose predicates, the common case, qualify nothing and it never parses a command out of a sentence) — the cmd-layer close handler mints exactly one `observed`-derivation PROPOSED memory candidate (`internal/mem.OfferStandingProofGraduation`, content-addressed under `COMPOUND_HOME/observed/standing-proof/`, never a ledger byte, never auto-promoting) offering to graduate that verbatim proof command into a STANDING re-verified proof (a job-roster entry or a proof-check gate) via adjudication. It carries the work_id, the command verbatim, and the close receipt ref; dedup is keyed on work_id + command (not day-salted), so an idempotent re-close never mints a duplicate and never resets an in-flight adjudication verdict. Like its siblings the mint lives at the cmd layer (spine never imports the mem mint door) and can never fail the already-successful close — a mint failure surfaces as a visible stderr warning while the close stands.
Repository identity is envelope authority, not path inference: `target_worktree_root` only locates the checkout. Create and governed legacy binding derive `repository_fingerprint` from the object format, expected-base lineage roots, and exact trimmed origin, overwriting caller input. Action identity, Workbench, dispatch, worker prompts, land-check reports, and content-sealed proof carry the fingerprint; every delivery validation re-derives it at the immutable expected base. Descendant commits preserve identity, but a changed origin, different lineage, or repository replacement at the same path fails closed and cannot silently rebind the WorkEnvelope. This is not an atomic whole-repository snapshot: close prepares exact target/publication ref locks, performs one final fingerprint revalidation while those locks are held and before terminal persistence, then guarantees only those ref values through the terminal event write. Git does not lock origin config or lineage identity; changes after the final fingerprint check are outside this transaction and surface on the next authoritative validation.

Versioned-byte rule: unchanged hash-bound envelope schemas preserve omitted legacy fields and carry a frozen pre-field JSON/hash fixture. Adding digest-covered sealed content bumps its schema and carries a frozen previous-version fixture; readers classify that version before recomputing with the current codec. A historical artifact can be stale, but must never be silently rewritten or falsely reported as tampered.

**Hit-authority discriminator (frozen).** Every result the engine returns declares STRUCTURALLY what authority it claims — exactly two legitimate shapes plus one violation, so an unowned pointer can never be silently dropped into (or out of) recall:

- **`index_hit`** — a pointer into owned canon; carries a `claim_id` that MUST resolve to a current ledger claim (the `byID` allowlist). An `index_hit` whose id is not owned is the engine serving authority it lacks: a hard `ErrEngineServedUnownedClaim` failure that refuses the whole query (fail-closed, like the embedder-mismatch refusal), never a silent drop. The empty kind (`""`) is `index_hit`, so a legacy engine emitting only resolvable pointers is unaffected.
- **`observed_fact`** — a candidate-shaped proposal surfaced over rented breadth that Compound does NOT own; carries no `claim_id` and no authority. It reaches canon ONLY as an `observed` candidate, adjudicated by code, never auto-promoted, and never in ambient recall. Its provenance shape is fixed: state `proposed`, derivation `observed` (distinct from `inferred` for provenance legibility), provenance = the engine name (as source lane) plus source-trace `engine:<name>:breadth`, promotion basis none, and it lands ONLY in the candidate inbox (`inbox/memory-candidates/`) — zero ledger bytes. The candidate id is content-addressed on entity/predicate/object, so re-surfacing the same fact is idempotent and never resets an in-flight adjudication verdict. Transient live-prompt retrieval uses the same validation/router path in no-capture mode, so malformed hits still fail closed while a valid observed-fact echo cannot persist the raw query.
- **Anything else** — an empty id with no observed payload, an `observed_fact` carrying a `claim_id`, an `index_hit` carrying an observed payload, or an unknown kind — is a violation (`ErrEngineServedUnownedClaim`). In `memory engine-doctor` a served-authority breach populates `engine_violations` as a hard failure while `ledger_unchanged` stays true (the breach is served authority, not a ledger mutation).

**Large tool-output externalization (C3, frozen).** Today's `PostToolUse` seam throws the tool body away and records only the tool name. C3 captures a LARGE tool body — one at or beyond the whole context budget (`MaxContextChars`, the same ~6000-char cap a ContextPack is built to) — so it can never flood the window, and it does so under the SAME never-own discipline as `observed_fact`:

- **Content-addressed & rebuildable.** `cid = "sha256:"+hex(sha256(body))`; the body is written to `COMPOUND_HOME/observed/tool-output/<cid>` — a REBUILDABLE directory (like indexes/projections), NEVER under `COMPOUND_HOME/ledger`. The same body yields the same cid (idempotent); reading a missing cid is an EXPLICIT error, never a silent nil, and a malformed/path-shaped cid is refused before any read.
- **observed-class only.** Each capture mints exactly ONE memory candidate with derivation `observed`, state `proposed`, promotion basis none (so it can never auto-promote), provenance lane = the tool name, source-trace `tool-output:<cid>`, and `snippet_hash` over a bounded head snippet. It lands ONLY in `inbox/memory-candidates/` — zero ledger bytes. The candidate id is content-addressed on the cid, so re-capturing the same body is idempotent and never resets an in-flight adjudication verdict.
- **Never `index_hit`, never ambient.** The body never enters `claims.jsonl`, so it is not a Claim: it can never become a ContextPack `Included`/`active_memory` ref, and the hit-authority router hard-fails any engine that tries to serve it as an `index_hit`. It is discoverable only via `compound memory show-output <cid>` (v1). `LedgerDigest()` stays byte-identical across capture (EngineDoctor stays green), because capture writes ONLY through the rebuildable blob dir and the candidate inbox — never a ledger append. Only the compact pointer (`tool-output:<cid> tool=… bytes=…`) flows back into the hook summary; the body never does.
- **Follow-up (documented, not built).** The blob dir has no size cap or GC in v1. Bounding total bytes / evicting blobs whose candidate was rejected or expired is a deliberate follow-up; capture stays append-only-idempotent for now.

## Distillation & capability-growth contracts (the compounding layer — P6 continuation + P8)

These turn traces into *adjudicated, versioned* knowledge and grow capability from evidence. They **extend**
the candidate loop and the `Claim` / `Capability` / `RegistryEntry` rows above — they do not replace them.
Defined here; implemented when a slice needs them (the candidate fan-out + as-of recall already exist in
`internal/mem`). Invariant throughout: **model extracts, code decides; no candidate reaches ambient recall
unadjudicated; distillation proposes candidates only.**

`LLMExtractionRequest` is the provider-neutral request packet. It carries bounded raw trace text,

## Entity resolution — the precedence order (the root of anti-fragmentation)

`NotesApp` / `notes-app` / a bundle id / "that app with the metrics" must collapse to **one** entity:

```text
1. explicit compound entity id
2. registry alias
3. repo / app / product fingerprint (remote, bundle id, package name, deploy target)
4. scope-resolver match ABOVE a confidence threshold
5. otherwise → a NEW candidate entity, PARKED until reviewed
```

An **uncertain** match creates **parked evidence only — never a promoted claim.**

## Shared fields that bend behavior

- **`source_class`** (on the universal header) — `source | generated | evidence | review | runtime |
  private_overlay`. Prevents *retrieved ≠ relevant ≠ authoritative ≠ current*. Only some classes are ambient.
- **`second_order_risks[]`** — every affordance is an attractor; declare what it makes more likely and can
  fossilize/flatten (`../transition.md`). Selection is ensemble-aware, not lookup.
- **`temperature` (memory) / `move_type` (receipts)** — make Law 5 and Law 15 measurable. Canonical
  `move_type` enum: `outward_delta | memory_delta | rule_delta | control_plane_repair | audit_only`. A
  `control_plane_repair` only counts when it removes a duplicate owner, fixes a recurring failure, or creates
  runtime proof — otherwise `audit_only`, which does not count.

## Distiller Improvement Review Gate

`compound distiller eval <case.json|cases-dir> --record` stores passing eval proof under `COMPOUND_HOME/reviews/distiller-eval/proofs/` and prints a `distiller_eval:*` or `distiller_eval_corpus:*` proof ref. `compound distiller improvement-plan --candidate <id>` writes JSON/Markdown review artifacts plus gated `.review.yaml` under `COMPOUND_HOME/reviews/distiller-improvements/`. `compound distiller improvement-review <review.yaml>` validates edited decision/rationale/confidence, requires `eval_proof_refs` for accept, and resolves each accepted proof ref to a recorded passing eval proof before emitting a reviewed improvement artifact. It does not mutate distiller policy, edit prompts/code, update eval corpus, call a model, mutate source owners, or promote memory truth.
