# distribution branch

Load for the actual distribution task. Use the [common execution contract](../README.md#common-execution-contract); this file grants no action authority.

## Trigger and input

A product needs more qualified buyers, someone asks for its next distribution step, or a launch/campaign hypothesis names an audience and channel.
Input: who buys and the moment they need it, how those buyers find and judge tools like this today, current funnel evidence, unit economics, and existing accounts and grants.

## Choose the medium before the message

No medium is a default. A missing social account, a checked brand file or a drafts-only queue is one option among several, never the next required step. Pick from the buyer's real path to purchase:

| Medium | Choose it when evidence shows | One bounded test |
|---|---|---|
| Store | buyers search the store with a task word, or the store result and page are the weak step | one listing change; impressions → first downloads → paid units, equal windows before and after |
| Practical search guide | buyers search the web with the problem before they know a product exists | one guide that solves the problem truthfully, then names the product; query impressions → qualified visits → store clicks → installs |
| Demo | the value shows in seconds and the doubt is "does it really do that" | one real capture of the core moment where buyers already arrive |
| First-party field test | the claim depends on conditions only real use shows | a dated test run by the team, with method, raw result and limits stated as such |
| Earned expert review | a qualified professional's check would remove the buyer's main doubt | only after a reviewer actually reviewed: record role, scope, exact corrections and permission before quoting; until then a draft question, never a claim or endorsement |
| Partner or community | a trusted group already gathers around the problem and its rules allow the contribution | one useful contribution under the product's own identity in one place; replies and referred installs |
| Owned social account | that account already reaches these buyers, or evidence says they discover tools in that feed | posts from that product's own account only; reach is not the result, installs and paid units are |
| No new channel | the funnel breaks after arrival, the sample is too small to read, or no medium is worth its cost | fix the leak or observe; record why no new channel was chosen |

1. **Exploration.** Name two or three candidate media with the buyer evidence for each. Mark every claim observed, inferred or missing.
2. **Decision.** Pick one. Compare expected qualified buyers per hour of attention and per unit of spend against current proceeds. Prefer media that reuse existing listings and pages when proceeds are small. Record the rejected media and why.
3. **Chosen action.** Define one bounded test: discovery → qualified visit → install → paid, with baseline window, test window, stop rule, attention cap in hours and cost cap. Name every link in that chain that cannot be measured yet; a test that can only measure reach says so before it starts.
4. **Observed result.** Read the same chain when the window ends. Record supported, refuted or inconclusive, and the next choice.

Record the decision where the growth audit reads it (a learned fact for `acquisition_channels`) and the test through the product hypothesis/review loop. If that import would restate contested product claims, keep the decision in the product's current brief and report the gap. A separate plan file is not the record.

An explicit operator request that names a medium ("queue this to X") skips selection: route it to the posting owner under its current grants and record the result. Private exploration (a long-term idea, a musing, a self-description) stays exploration. Do not turn it into posts, offers, prices or public promises unless the operator asks.

## Procedure and composition

Prepare variants and medium-specific assets with a truthful offer. For outbound, read ../references/outbound.md before account or message effects. Dedupe campaigns and check suppression/cooldown/provider limits. Demand generation is not the fix for broken first value.
Optional complement: marketing/copy/SEO/email/launch methods only for the selected medium. Verify installation, provenance and its narrower contract before loading. Do not import an external body merely because this branch names it.

## Output and proof

A recorded medium choice with rejected options and evidence, one bounded measurable test with its window, or an explicit no-op with its reason; authorized delivery evidence with recipient/channel provenance when the test runs.
Next context: activation for journey friction; measurement after exposure and window maturity. Record source/entity revision, falsifier, uncertainty and named receiving owner; require actual acknowledgment/consumption before claiming handoff. See the [source catalog](../SOURCES.md) for conceptual credits, not efficacy evidence.

## Silence and recovery

Addresses are not send permission. No fake warm-up, identity rotation, unsolicited bulk effects or automatic publication. No invented reviewers, testimonials, results or first-person experience.
A missing account, brand file or posting grant blocks only a test that chose that medium. It never blocks the product's other tests and never becomes a human step by default.
Persist operation/provider IDs; reconcile ambiguous submission before retry. Stop on revoked grants or declared health thresholds.
Duplicate/stale events, unavailable capacity/consumer, immature windows or a missing grant select no-op, bounded observation or explicit defer. A routing offer proves none of execution, recovery, operator-time savings or business impact.
